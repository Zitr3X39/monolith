# MONOLITH MCP — хранилище для агентов и ИИ

Это маленький сервер, который отдаёт твоё хранилище ссылок наружу по
протоколу MCP. Notion, Claude, Cursor и любой другой агент подключаются к
нему как к обычному коннектору — и дальше могут искать у тебя, читать
материалы целиком и находить снаружи то, чего у тебя нет.

Важное правило, зашитое внутрь: **читать можно всегда, писать — только с
твоего разрешения.**

---

## Что умеет

| Инструмент | Что делает |
| --- | --- |
| `search_vault` | Смысловой поиск по твоим ссылкам: по тегам, категориям, твоим заметкам, домену. Понимает русский и английский, синонимы, транслит и опечатки. |
| `get_item` | Открывает материал и отдаёт **текст целиком**: для GitHub — README, для сайтов и статей — читаемый текст без рекламы и бейджей. |
| `list_topics` | Карта хранилища: все категории со счётчиками, частые теги, размер, дата обновления. |
| `find_external` | Ищет **в интернете** то, чего у тебя нет: репозитории GitHub, awesome-каталоги, скиллы, пакеты npm. Форки, архивы и заброшенное отбрасывает. |
| `add_link` | Добавляет найденное в хранилище. Только если ты явно разрешил (см. шаг 5). |

В ответах всегда написано, своё это или внешнее. Агент не может случайно
выдать находку из интернета за то, что у тебя уже есть.

## Шаг 1. Выложить сервер

Способ первый — одной командой с компьютера:

```
cd mcp
npx wrangler deploy
```

Первый раз откроется браузер и попросит войти в Cloudflare — это бесплатно.
В конце команда напечатает адрес вида:

```
https://monolith-mcp.ТВОЙ-ПОДДОМЕН.workers.dev
```

Этот адрес и есть твой сервер. Сохрани его.

Способ второй — вообще без командной строки:

1. Зайти на `dash.cloudflare.com` → **Workers & Pages** → **Create** → **Worker**.
2. Назвать `monolith-mcp`, нажать **Deploy**, потом **Edit code**.
3. Стереть весь код в редакторе и вставить содержимое файла `mcp/worker.js`.
4. Нажать **Deploy**. Адрес появится сверху.

## Шаг 2. Проверить, что живой

Открой в браузере адрес и добавь в конец `/health`:

```
https://monolith-mcp.ТВОЙ-ПОДДОМЕН.workers.dev/health
```

Должно ответить примерно так:

```json
{ "ok": true, "links": 35, "categories": 36, "updated_at": "…" }
```

Если просто открыть адрес без `/health`, браузер покажет короткую подсказку —
это нормально, сервер общается не с браузером, а с агентами.

## Шаг 3. Подключить к Notion

1. В Notion: **Настройки** → **Подключения** → добавить свой MCP-сервер.
2. Вставить адрес Worker.
3. Сохранить.

После этого можно писать в чате обычными словами:

- «посмотри у меня в хранилище, что есть про оффлайн и кэш»
- «прочитай мне этот репозиторий целиком и скажи, годится ли»
- «у меня нет ничего про MCP — найди снаружи 5 нормальных проектов»

Агент сам выберет нужный инструмент.

В Claude Desktop или Cursor — то же самое, только адрес прописывается в их
настройках MCP-серверов (поле `url`).

## Шаг 4 (по желанию). Пароль на сервер

По умолчанию адрес открыт: кто знает ссылку — может читать хранилище.
Хранилище и так публичное на GitHub Pages, так что это не утечка. Но если
хочется закрыть:

```
npx wrangler secret put AUTH_TOKEN
```

Придумай строку-пароль. После этого клиент должен присылать заголовок
`Authorization: Bearer твой-пароль` — в Notion и Cursor это поле «токен».

## Шаг 5 (по желанию). Разрешить агенту добавлять ссылки

Нужно **три** вещи одновременно, иначе запись не сработает:

1. Токен GitHub:
   ```
   npx wrangler secret put GITHUB_TOKEN
   ```
   Создать его на `github.com/settings/tokens` → fine-grained token → доступ
   только к репозиторию `monolith` → права **Contents: Read and write**.
2. В Cloudflare: **Settings** → **Variables** → поставить `WRITE_ENABLED` = `1`
   (или заменить `"0"` на `"1"` в `wrangler.toml` и задеплоить снова).
3. Агент обязан передать `confirm: true` — то есть сначала спросить тебя.

Пока `WRITE_ENABLED` не равен `1`, любая попытка записи вернёт вежливый
отказ: «Запись выключена, сейчас я только читаю». Выключить обратно можно в
любой момент — вернуть `0`.

Новая ссылка уходит прямо в `data/links.json` в репозитории, и через
минуту-две появляется на сайте сама.

## Если что-то не так

- **`401` и просьба про ключ** — включён `AUTH_TOKEN`, добавь его в клиенте.
- **Браузер показывает подсказку вместо JSON** — так и задумано, это не ошибка.
- **«GitHub ограничил число запросов»** — без токена GitHub даёт всего 60
  запросов в час на поиск. Добавь `GITHUB_TOKEN` (шаг 5, пункт 1) — станет 5000.
- **Добавил ссылку на сайте, а сервер её не видит** — сервер держит хранилище
  в памяти 5 минут, чтобы отвечать быстро. Подожди немного.
- **Сервер отвечает, но находит мало** — так и задумано: фильтры отбрасывают
  форки, архивы, проекты без описания и всё, что не обновлялось больше двух
  с половиной лет. Лучше мало и по делу, чем много и мусор.

## Как это связано с сайтом

Логика поиска здесь **та же самая**, что в `assets/search.js` на сайте:
одни и те же синонимические кластеры, тот же стемминг, транслит, устойчивость
к опечаткам и те же фильтры внешних источников. Поэтому на один и тот же
вопрос сайт и агент отвечают одинаково.

Если правишь кластеры в одном месте — поправь и во втором.
